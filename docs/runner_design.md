# Qwen3 Abbreviation Study Runner — Design Contract

## Scope

This Python system runs already-prepared abbreviation prompts against:

- Qwen3 4B through the Hugging Face router with Featherless AI; and
- Qwen3 8B, 14B, and 32B through OpenRouter.

It does not generate synthetic abbreviations or prompts. A change from the
32-row bridge dataset (29 sets) to the frozen 900-row, three-condition V3 dataset must
require only a dataset/configuration change.

The runner is offline-safe by default. Network requests are possible only when
the caller supplies `--execute`. A dry run must not require credentials.

Cost and final-answer length are intentionally outside the data model.

## Package boundaries

The implementation will use this package layout:

```text
qwen_abbrev_study/
  __init__.py          Public version and package metadata
  cli.py               Argument parsing and dry-run/--execute safety gate
  config.py            Configuration loading and semantic validation
  datasets.py          CSV/JSONL loading and prompt-row validation
  ids.py               Exact-prompt hashing and stable run-ID construction
  models.py            Typed normalized request/result records
  runner.py            Ordering, resume behavior, retries, and orchestration
  storage.py           Manifest plus append-only result/attempt JSONL logs
  truncation.py        finish_reason/native_finish_reason classification
  providers/
    base.py            Provider interface and normalized provider response
    huggingface.py     Hugging Face/Featherless streaming adapter
    openrouter.py      OpenRouter streaming adapter and metadata lookup
```

Tests will use fake transports and recorded stream fragments. They must not
contact either provider.

## Prompt dataset contract

The canonical dataset format is JSONL: one JSON object per prepared prompt.
CSV input will also be supported for convenient exports.

Required fields:

- `prompt_id`: unique, stable identifier for the prompt row.
- `set_id`: identifier for the matched abbreviation set.
- `prompt`: prepared prompt text. It is never generated by the runner.

Recommended study metadata includes `condition`, `domain`, `abbreviation`, and
`target_expansion`. Other dataset columns are allowed and preserved under
`dataset_metadata` in results.

Validation rules:

- IDs and prompt text must be nonempty strings.
- `prompt_id` must be unique within the file.
- The prompt is preserved character-for-character, including whitespace.
- Optional configured expected row/set counts must match exactly.
- The same loader handles the 32-row/29-set bridge input and the later
  frozen 900-row V3 input.

The machine-readable row contract is
[`schemas/prompt.schema.json`](../schemas/prompt.schema.json).

## Configuration contract

A configuration selects the dataset, a new experiment identity and output
directory, generation/retry settings, strategies, and model routes.

The four routes are:

| Model key | Gateway | Requested model ID | Requested provider |
|---|---|---|---|
| `qwen3_4b` | `huggingface` | `Qwen/Qwen3-4B:featherless-ai` | `featherless-ai` |
| `qwen3_8b` | `openrouter` | `qwen/qwen3-8b` | router-selected |
| `qwen3_14b` | `openrouter` | `qwen/qwen3-14b` | router-selected |
| `qwen3_32b` | `openrouter` | `qwen/qwen3-32b` | router-selected |

The config contains credential environment-variable names, never credential
values. `HF_TOKEN` and `OPENROUTER_API_KEY` are read only after `--execute`.

Every fresh collection uses a new `experiment_id` and output directory. An
existing output directory is accepted only with an explicit resume option and
only when its manifest matches the experiment, configuration, and dataset.

The machine-readable configuration contract is
[`schemas/config.schema.json`](../schemas/config.schema.json).

## Exact prompt and run identity

`dataset_prompt` is the unmodified text loaded from the dataset.

`prompt` is the exact user-message content submitted to the provider after
deterministic strategy and model prompt controls are applied. For example, a
Hugging Face/Featherless route may append `\n\n/think`. No hidden whitespace
normalization is permitted.

`prompt_sha256` is the lowercase, 64-character SHA-256 digest of the UTF-8
encoding of `prompt`.

The complete run ID is:

```text
experiment=<url-encoded experiment_id>|model=<url-encoded requested model ID>|strategy=<url-encoded strategy ID>|prompt=<url-encoded prompt_id>|prompt_sha256=<64 lowercase hex characters>
```

No component or hash is truncated. Encoding components prevents delimiters in
user-defined values from making the ID ambiguous.

## Output directory and persistence

Each experiment owns one directory:

```text
<output_dir>/
  manifest.json
  results.jsonl
  attempts.jsonl
```

- `manifest.json` records the dataset/config hashes, selected routes, ordering
  seed, execution mode, and timestamps. It contains no secrets.
- `results.jsonl` is append-only and stores one normalized terminal result for
  every attempted run. The latest record for a run ID is authoritative.
- `attempts.jsonl` is append-only and stores every successful or failed API
  attempt, including retryable failures.

JSONL is the source of truth because it preserves JSON `null` exactly. Every
unavailable provider value is `null`, never an empty string or inferred zero.

## Result contract

Every result includes:

- exact `dataset_prompt`, transmitted `prompt`, and `prompt_sha256`;
- completion text and reasoning text, with unavailable reasoning as `null`;
- prompt, completion, reasoning, and total token counts;
- normalized and native finish reasons;
- requested and actual model/provider IDs;
- generation ID and request ID as separate nullable fields;
- success/failure status, total attempts, and failed-attempt count;
- retry count (`attempts - 1`);
- structured terminal error details;
- total response latency and optional time to first token; and
- derived truncation.

No result contains cost fields, response-character counts, response-word
counts, or final-answer token counts.

`total_latency_ms` measures the final attempt from request start until its
stream/body is fully consumed or fails. Each attempt has its own latency in
`attempts.jsonl`. `operation_elapsed_ms` additionally records end-to-end runner
time across retries and backoff, making the timing interpretation explicit.

The machine-readable result contract is
[`schemas/result.schema.json`](../schemas/result.schema.json), and each retry
record follows
[`schemas/attempt.schema.json`](../schemas/attempt.schema.json).

## Retry and failure semantics

The default maximum attempt count is three. Retryable conditions include
timeouts, connection interruptions, HTTP 408/409/429, and HTTP 5xx responses
commonly associated with transient failures. Authentication, authorization,
invalid-request, and other permanent failures are not retried.

For a successful first request:

- `attempts = 1`
- `retries = 0`
- `failed_attempts = 0`
- `success = true`
- `error = null`

For two failures followed by success:

- `attempts = 3`
- `retries = 2`
- `failed_attempts = 2`
- `success = true`
- `error = null`

For a terminal three-attempt failure:

- `attempts = 3`
- `retries = 2`
- `failed_attempts = 3`
- `success = false`
- `error` contains the final structured error

## Finish reasons and truncation

Truncation is derived from both `finish_reason` and `native_finish_reason`.

- `true`: either reason unambiguously indicates an output/token/length limit.
- `false`: at least one available reason is a recognized normal termination
  and neither reason indicates truncation.
- `null`: both reasons are unavailable or only unknown values are available.

The exact mapping will be centralized and unit-tested. Conflicting signals are
resolved conservatively: an explicit truncation signal wins.

## CLI safety and resume rules

Planned commands:

```bash
# Safe default: validate only, no credentials and no network.
python -m qwen_abbrev_study --config config.json

# Also safe and explicit.
python -m qwen_abbrev_study --config config.json --dry-run

# Live requests require explicit authorization.
python -m qwen_abbrev_study --config config.json --execute
```

The parser rejects combining `--execute` and `--dry-run`. Tests will inject a
transport that fails immediately if contacted during dry-run validation.
